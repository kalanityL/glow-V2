5. Le traitement ↑ sommaire

Ce chapitre décrit les objets stockés du domaine — journal des prises, identifiant de traitement dans le profil, fiche du catalogue — et les calculs qui en sortent : résolution du traitement d'une ligne, regroupement par molécule, modèle pharmacocinétique de Bateman, séries de la home, paliers de dose, fenêtres temporelles. Il donne les formules, les unités, les seuils, l'ordre des opérations et les cas limites ; les écrans qui les affichent sont décrits dans la spécification fonctionnelle.

Entités

Trois objets sont stockés : la ligne de journal InjectionLog, les champs de traitement du profil, et — en dur dans le code, non modifiable par l'utilisatrice — la fiche Treatment. Tout le reste est dérivé à la lecture.

Fenêtres temporelles

Six fenêtres : 7days, 14days, 30days, 90days, all, custom. Défaut 30days. La coupure est une chaîne de date locale, comparée aux dates des entrées comme des chaînes — jamais convertie en Date, ce qui ferait intervenir un fuseau.

getCutoffDateStr(w) :
  'all'    → null                                    // pas de coupure
  'custom' → customRange.startDate si lisible, sinon null
  sinon    → getLocalDateStr(aujourd'hui − (WINDOW_DAYS[w] − 1) jours)
             WINDOW_DAYS = { 7days:7, 14days:14, 30days:30, 90days:90 }

filterByTimeWindow(items, w, getDate, range) :
  'all'    → tous

toTreatmentId(stored) :
  1. stored === undefined | null            → undefined   // « le traitement du profil »
  2. identifiant connu du catalogue          → lui-même
  3. libellé historique (table)              → son identifiant

  5. looksOralByName(stored) ? 'autre-comprime' : 'autre-injection'

Zone proposée : voisinage aléatoire

La suggestion écarte la zone de la prise la plus proche avant l'instant visé et celle de la plus proche après, puis tire au sort parmi les zones restantes.

  pour chaque prise dont le site ∈ ROTATION_SITES et dont l'instant est lisible

Fréquence observée des prises

L'écart moyen entre deux journées de prise, mesuré sur les seules prises survenues.

injectionIntervalDays(history, now = maintenant) :
  dates = [...new Set(
             history.filter(log => hasOccurred(log.date, log.time, now))
                    .map(log => log.date))].sort()
  dates.length < 2 → null
  ecart = daysBetween(dates[0], dates.at(-1))
  ecart <= 0 → null
  → ecart / (dates.length − 1)

Ce sont des journées, pas des lignes : deux prises le même jour ne comptent pas pour un écart nul, ce qui raccourcirait la fréquence annoncée. La moyenne ne dépend que des deux extrémités, elle ne masque donc pas les semaines sautées. Le calcul porte sur tout l'historique fourni, sans distinction de traitement.
