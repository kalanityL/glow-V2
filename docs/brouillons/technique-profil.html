19. Profil, avatar, compte, avis, sondage, FAQ, légal ↑ sommaire

Ce chapitre donne les règles de calcul et de décision du profil, de l'avatar, des modules, des rappels, du compte, des envois d'avis et de sondage, de la FAQ et de l'acceptation légale. Il dit les bornes, les messages exacts, les défauts, l'ordre des opérations et ce qui part en base.

Entités

Le profil est un objet unique, enregistré avec les journaux sous une seule clé. Les grandeurs sont en unités canoniques : années, centimètres, kilogrammes, HH:MM et AAAA-MM-JJ en heure locale. Aucune unité n'est stockée à côté de la valeur.

Aperçu profil du PlusMenu

Deux chiffres, calculés au rendu de la carte. → fonctionnelle

startingWeight = getStartingWeight(weightHistory)            // 0 si aucune pesée marquée départ
currentWeight  = weightHistory.length > 0
                 ? weightHistory[weightHistory.length - 1].weight
                 : startingWeight
weightLost     = startingWeight - currentWeight
affichage      = '-' + parseFloat(weightLost.toFixed(1)) + ' kg'
lastInjection  = getMostRecentPastInjection(injectionHistory)
                 // la plus récente d'instant ≤ maintenant ; à défaut, la plus récente de toutes
affichage      = lastInjection ? lastInjection.dose + ' mg' : 'N/A'

La « dernière pesée » est la dernière ENTRÉE du tableau, pas la plus récente par date : aucun maximum n'est recalculé. L'ordre stocké ne suit les dates que si toutes les écritures le tiennent, et elles ne le tiennent pas — addWeighIn retrie à l'ajout sur date seule, sans l'heure, tandis que updateWeighIn ne retrie pas du tout. Poids de départ et objectif

Un poids est une chaîne à une décimale, strictement positive et au plus 1000 kg.

sanitizeWeight(raw) :
  cleaned = cleanDecimalInput(raw)
  n = Number(cleaned)
  si cleaned === '' ou !Number.isFinite(n) ou n <= 0 ou n > 1000 → null
  sinon cleaned            // la chaîne nettoyée, jamais reformatée

Refus : « Un poids entre 0,1 et 1000 kg est attendu. » RULE_WEIGHT : min 0.1, max 1000, decimals 1, step 0.1, unité « kg », même message. Les deux planchers écrits — 0,1 pour la règle du champ, « strictement positif » pour le sanitize du profil — décident pareil : les deux nettoyages tronquent à une décimale, et aucune valeur de ]0 ; 0,1[ n'y survit.

Nettoyage décimal

cleanDecimalInput est le nettoyage propre aux poids du profil, appliqué à chaque frappe. Il ne borne rien et n'arrondit rien.

1. toutes les virgules deviennent des points
2. tout ce qui n'est ni chiffre ni point est retiré (le signe moins compris)
3. s'il reste plus d'un point, seul le premier survit :
   parts[0] + '.' + parts.slice(1).join('')
4. la partie décimale est tronquée à 1 chiffre

Moment du jugement et retour arrière (NumberField)

Le champ numérique ne juge qu'à la sortie : perte du focus, ou touche Entrée. Pendant la frappe, seul cleanNumericInput s'applique. Le champ retient dans une ref la dernière valeur VALABLE traversée, initialisée à la valeur d'ouverture si elle est acceptable et à la chaîne vide sinon.

commit() :
  retained = sanitizeNumber(value, rule)
  si retained === null :
     si validateOnSubmit : onCommit(value) ; fin       // ni message ni retour
     announce(boundsMessage(rule))
     initial = lastValid.current
     onValueChange(initial) ; onCommit(initial)
  sinon :
     announce(null) ; lastValid = retained
     si retained !== value : onValueChange(retained)
     onCommit(retained)

Le message part dès qu'une frappe redevient acceptable, sans attendre une nouvelle sortie. En mode validateOnSubmit — celui des quatre champs chiffrés du formulaire complet — le champ ne dit rien, ne revient pas, et la saisie refusable reste sous les yeux jusqu'au clic sur Valider.

Flèches clavier sur un champ numérique

Les flèches Haut et Bas sont reprises à la main : le champ est un type="text", sans compteur natif. L'événement est arrêté (preventDefault) et le refus en cours est effacé.

stepNumber(raw, rule, direction) :
  decimals = rule.decimals ?? 0
  step     = rule.step ?? 10 ** -decimals
  cleaned  = cleanNumericInput(raw, decimals)
  si vide ou '.' → String(Math.max(rule.min, 0))
  next    = current + step * direction
  bounded = min(rule.max, max(rule.min, next))       // max ignoré s'il est absent
  rendu   = String(Math.round(bounded * 10**decimals) / 10**decimals)

Pas effectif : 1 pour l'âge et la taille (aucun step, 0 décimale), 0,1 pour les deux poids.

Édition en place d'une case du profil

Une case du récapitulatif tient son brouillon ; ouvrir efface le message. Deux chemins selon qu'une règle numérique est fournie.

case de TEXTE (prénom) — commit() du composant :
  retained = sanitize(draft)
  si null : draft ← valeur enregistrée ; message ← refusal ; rien n'est écrit
  sinon   : message ← '' ; si retained !== value → onCommit(retained)
  la frappe efface le message dès que sanitize(next) !== null

case CHIFFRÉE (âge, taille, poids de départ, objectif) :
  NumberField juge seul (showMessage=false) ; onRefusal alimente le message
  onCommit(retained) → si retained !== value, la case enregistre

Dans les deux cas, rien n'est écrit quand la valeur retenue est égale à la valeur enregistrée. Les six gestes d'enregistrement sont mémoïsés dans la page ; le poids de départ passe par onSaveStartingWeight, les cinq autres par onSaveProfile.

Le poids de départ n'est pas un champ du profil : c'est la pesée qui porte isStartingWeight. handleSaveStartingWeight(kg) appelle setStartingWeight(history, roundWeight(kg)).

  depart = history.find(w => w.isStartingWeight)
  si depart : history.map(w => w.id === depart.id ? { ...w, weight: kg } : w)
              // date, heure et mensurations intactes

Nettoyage numérique générique

cleanNumericInput(raw, decimals = 0) est le nettoyage de frappe commun à tous les champs numériques du site. Il ne borne pas : taper « 1 » en route vers « 168 » reste possible sous un minimum de 50.

1. virgules → points ; tout sauf chiffres et points retiré (moins compris)
2. plus d'un point → parts[0] + '.' + parts.slice(1).join('')
3. decimals === 0 → seule la partie entière est gardée
4. sinon la fraction est tronquée à `decimals` chiffres

Message par défaut d'une règle

boundsMessage(rule) rend rule.message s'il existe. Sinon il compose à partir des bornes, en écrivant les nombres avec formatNumber(valeur, decimals).

avec max : « Une valeur entre {min} et {max}{ unité} est attendue. »

Les trois règles du profil portent leur propre message : les phrases génériques ne sont pas genrées.

Un seul document par compte, fusionné dans une transaction qui a lu l'état précédent.

mergeDocumentOnce(`surveys/${uid}`, current => {

  crossing    = updateCount > SURVEY_UPDATES_ALERT_THRESHOLD (10)
                && current?.updatesAlertSent !== true

Validation numérique à la sortie

sanitizeNumber(raw, rule) rend la chaîne retenue, ou null. Elle rend une CHAÎNE et non un nombre : c'est elle qui sera réaffichée.

decimals = rule.decimals ?? 0
cleaned  = cleanNumericInput(raw, decimals)
si cleaned === '' ou '.'          → rule.allowEmpty ? '' : null
si !Number.isFinite(Number(cleaned)) → null
si valeur < rule.min                 → null
si rule.max défini et valeur > max   → null
sinon cleaned, moins un point final orphelin

Le nettoyage précède le jugement : la troncature à decimals chiffres est déjà faite quand les bornes sont comparées. La chaîne n'est jamais reformatée : « 70 » reste « 70 » et ne devient pas « 70.0 ». isAcceptable(raw, rule) est sanitizeNumber(raw, rule) !== null.
