18. Modules et rappels ↑ sommaire

Ce chapitre donne les drapeaux qui commandent les sept modules, la fonction qui les lit défaut compris, le masquage et les surfaces qu'il modifie. Il donne aussi les champs des deux rappels, leurs valeurs par défaut, l'arrondi appliqué à l'enregistrement et la composition des deux récapitulatifs.

Entités

Aucun objet propre : tout tient dans UserProfile, écrit en entier dans le JSON unique de l'application (clé glp1_app_companion_data, champ profile). Sept drapeaux d'activation, sept drapeaux de masquage, onze champs de rappel.

Trois drapeaux d'activation sont requis par le type (foodTrackingEnabled, stepsTrackingEnabled, sportTrackingEnabled) ; les quatre autres sont facultatifs. La colonne « Absent vaut » décrit ce que produit une sauvegarde antérieure à l'ajout du champ, que la fusion au chargement ou la lecture par défaut rattrape.

Dérivés, donc non stockés : l'état réel d'un module (isModuleOn), son masquage effectif (isModuleHidden), les listes de menus et de tiroirs, les deux phrases de récapitulatif, la mention « Rappels : … » de l'accueil, la vitre d'une page éteinte. La pesée (history) n'a aucun drapeau : elle n'est pas un module.

Défauts des modules

Deux jeux de défauts, opposés. treatmentTrackingEnabled et sideEffectsTrackingEnabled sont absents du profil d'usine et absents des sauvegardes antérieures au 2026-08-29 : leur absence vaut allumé. Les cinq autres drapeaux valent éteint en leur absence, et le profil d'usine INITIAL_PROFILE les écrit tous à false.

MODULES_ALLUMES_PAR_DEFAUT = { injection, symptoms }

isModuleOn(profile, tabId):
  flag = MODULE_FLAGS[tabId]
  si flag absent                      -> true          // history, report, plus…
  v = profile[flag]
  si v === undefined ou v === null     -> tabId ∈ MODULES_ALLUMES_PAR_DEFAUT
  sinon                                -> Boolean(v)

INITIAL_PROFILE : foodTrackingEnabled = stepsTrackingEnabled = sportTrackingEnabled
                = meTimeTrackingEnabled = sleepTrackingEnabled = false
                (treatmentTrackingEnabled et sideEffectsTrackingEnabled : non écrits)

Au chargement, le profil enregistré est fusionné par-dessus le profil d'usine : { ...INITIAL_PROFILE, ...parsed.profile }. Une sauvegarde sans les cinq drapeaux hors tête reçoit donc false à la lecture ; les deux drapeaux de tête, absents des deux côtés, restent undefined et sont lus comme allumés.

Bascule d'un module

Sept gestionnaires, un par module, tous bâtis sur le même corps. La valeur écrite est la négation de l'état lu défaut compris, pas du champ nu. Rallumer écrit en plus le masquage à false ; éteindre ne touche pas au masquage.

handleToggleX():
  actuel = profile.XTrackingEnabled ?? défautX        // false, sauf traitement/effets : true
  onSaveProfile({
    ...profile,
    XTrackingEnabled: !actuel,
    ...(actuel ? {} : { XModuleHidden: false })       // seulement quand on rallume
  })

La case « Masquer dans l'application. » écrit indépendamment : onSaveProfile({ ...profile, [field]: !Boolean(profile[field]) }). Aucun des huit gestes n'écrit ailleurs que dans le profil : les journaux du module ne sont pas touchés. Chaque geste passe par handleSaveProfile, qui arrondit targetWeight et ramène les deux heures de rappel aux minutes rondes avant d'écrire.

Masquage complet

Le masquage effectif est une conjonction : le module doit être éteint et son drapeau de masquage vrai. L'état d'extinction se lit par isModuleOn, jamais par le drapeau nu — sans quoi un traitement sans drapeau d'activation passerait pour éteint et son masquage mordrait.

MODULE_HIDDEN_FLAGS = { injection: treatmentModuleHidden, symptoms: sideEffectsModuleHidden,
                        meals: foodModuleHidden, steps: stepsModuleHidden,
                        sports: sportModuleHidden, metime: meTimeModuleHidden,
                        sleep: sleepModuleHidden }

isModuleHidden(profile, tabId):
  hidden = MODULE_HIDDEN_FLAGS[tabId]
  si hidden absent -> false
  return !isModuleOn(profile, tabId) AND Boolean(profile[hidden])

La case n'est rendue que sous une carte éteinte (!isXEnabled && masquerModule(…)) : module allumé, elle disparaît de l'écran, mais le drapeau garde sa valeur en base.

Les deux tiroirs partagent drawerItems(profile, order). Il construit la liste sur un profil dont les cinq drapeaux hors tête sont forcés à true — sans quoi allTabs, qui filtre déjà sur eux, rendrait la liste amputée —, retire les masqués, puis rend l'état réel à part. Chaque entrée garde l'objet MenuTab entier (id, label, icon), seul le libellé étant substitué : les deux tiroirs ont besoin de tab.id pour naviguer et de tab.icon pour le picto.

drawerItems(profile, order):
  base = { ...profile, foodTrackingEnabled: true, stepsTrackingEnabled: true,
           sportTrackingEnabled: true, meTimeTrackingEnabled: true, sleepTrackingEnabled: true }
  pickTabs(base, order)                              // ordre imposé par `order`
    .filter(tab -> !isModuleHidden(profile, tab.id))
    .map(tab -> {
       flag  = MODULE_FLAGS[tab.id]
       label = DRAWER_LABELS[tab.id]
       return { tab: label ? { ...tab, label } : tab,
                enabled: flag ? isModuleOn(profile, tab.id) : true }   // history : true
    })

ADD_DRAWER_ORDER     = injection, history, symptoms, sports, meals, sleep, metime
JOURNAL_DRAWER_ORDER = ADD_DRAWER_ORDER + steps
DRAWER_LABELS        = { history: 'Balance', meals: 'Menus' }

Seul le tiroir Journal réordonne : il rend [...items.filter(enabled), ...items.filter(!enabled)] — tri stable, les éteints ferment la liste sans que l'ordre de chaque groupe change. Le tiroir Ajouter ne trie pas : il parcourt addDrawerItems(profile) tel quel, dans l'ordre d'ADD_DRAWER_ORDER, et une case éteinte garde sa place au milieu de la grille à trois colonnes. Dans le tiroir Ajouter la case éteinte porte disabled ; dans le tiroir Journal elle reste cliquable et appelle onNavigateEteinte.

La page Badges ne lit ni isModuleOn ni Boolean(drapeau) : chaque définition porte son propre categoryEnabled(profile), et deux formes coexistent — p.sportTrackingEnabled !== false et p.stepsTrackingEnabled !== false d'un côté, p.foodTrackingEnabled === true de l'autre. Une catégorie non activée alimente la liste « à activer », sauf module masqué : inactiveCategoryBadges = ALL_BADGE_DEFINITIONS.filter(def -> !categoryEnabled(profile) && !isModuleHidden(profile, ongletDeCategorie(def))). Les quatre définitions couvrent trois catégories, toutes trois présentes dans la correspondance (« Nombre de Pas » → steps, « Activité Physique » → sports, « Repas et En-cas » → meals) ; une catégorie ajoutée hors table recevrait '', pour lequel isModuleHidden rend false.

État d'un module, défaut compris

MODULE_FLAGS associe sept identifiants de page à sept drapeaux : injection → treatmentTrackingEnabled, symptoms → sideEffectsTrackingEnabled, meals → foodTrackingEnabled, steps → stepsTrackingEnabled, sports → sportTrackingEnabled, metime → meTimeTrackingEnabled, sleep → sleepTrackingEnabled. Le tiroir Tendances ne lit pas cette table : il fixe l'état de chaque carte à la construction de ses lignes.

rows = [

  { key: weight, tab: history,   enabled: true },
  { key: meals,  tab: meals,     enabled: Boolean(profile.foodTrackingEnabled) },
  { key: sport,  tab: sports,    enabled: Boolean(profile.sportTrackingEnabled) },
  { key: metime, tab: metime,    enabled: Boolean(profile.meTimeTrackingEnabled) },

// la huitième carte, « Effets secondaires », est rendue hors de `rows`, avec enabled = true

Défauts du rappel d'injections

La carte lit six champs, dont cinq avec un repli. Le repli n'est pas écrit : il ne sert qu'à l'affichage tant que l'utilisatrice n'a rien choisi.

Minutes rondes

Huit minutes seulement sont retenues, et l'arrondi est vers le bas — jamais vers le haut, pour ne pas produire une heure future. La règle s'applique en deux endroits : le sélecteur ne propose que ces minutes, et l'enregistrement du profil y ramène les deux heures de rappel.

ROUNDED_MINUTES = [0, 10, 15, 20, 30, 40, 45, 50]

snapToRoundedMinutes(time):
  si time ne correspond pas à /^(\d{2}):(\d{2})$/  -> time inchangé
  minutes = Number(mm)
  si minutes > 59                                  -> time inchangé
  rounded = dernière valeur de ROUNDED_MINUTES ≤ minutes, sinon 0
  return `${hh}:${pad2(rounded)}`

handleSaveProfile(p):
  targetWeight        = roundWeight(p.targetWeight)          // Math.round(kg × 10) / 10
  reminderTime        = snapToRoundedMinutes(p.reminderTime)
  medicalReminderTime = p.medicalReminderTime ? snapToRoundedMinutes(p.medicalReminderTime)
                                              : p.medicalReminderTime

Tout geste des deux pages passe par handleSaveProfile : basculer un module, cocher un masquage, changer un jour de rappel ramènent au passage les deux heures aux minutes rondes.

Cas limites

new Date('2026-05-03') est interprété en UTC ; toLocaleDateString rend la date locale : dans un fuseau à décalage négatif, la veille s'affiche.

injectionReminderStartDate: '' venu d'une sauvegarde modifiée : le repli ?? ne rattrape que undefined et null, la chaîne vide passe, new Date('') donne Invalid Date et la phrase l'affiche. Aucune validation au chargement ne l'écarte.

medicalDate vide, en revanche, retire le bloc : cette phrase-là ne rend jamais « Invalid Date ».

L'heure est reprise brute du profil, sans reformatage : elle s'affiche telle qu'elle est stockée, en HH:MM.
