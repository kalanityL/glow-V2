9. Les pas ↑ sommaire

Ce chapitre décrit l'entité StepLog, les quatre constantes du module et les calculs qui en dérivent : objectif, pourcentage, distance, durée, calories, moyennes, cumul, points de graphe, tendance et sens. Il donne les formules telles qu'elles sont écrites dans le code, les fenêtres de filtrage au caractère près et les cas limites de chacune.

Entités

Un seul objet est stocké : StepLog. Tout le reste — distance, durée, vitesse, calories, pourcentage, moyennes, cumul — est calculé à la lecture et n'existe nulle part en base.

Formats communs des nombres et des dates

Tout nombre affiché passe par formatNumber(valeur, décimales = 0) : milliers groupés par trois avec U+00A0 (espace insécable, jamais U+202F), décimales après un point, zéros de queue supprimés, signe collé au nombre, chaîne vide pour NaN et ±∞. decimals est un maximum, pas une longueur. formatNumber1Dec en est l'appel à une décimale.

formatNumber(7300)      → "7 300"      (U+00A0)
formatNumber(82.4, 1)   → "82.4"
formatNumber(82, 1)     → "82"
formatNumber(9.68, 1)   → "9.7"
formatNumber(NaN)       → ""

format1Dec, qu'emploie le bloc du cumul, n'est pas un réexport du module de nombres : src/shared/number/index.ts n'exporte que formatNumber, formatNumber1Dec et NBSP. C'est une fonction distincte, définie dans src/features/home/homeOverview.ts, qui enveloppe formatNumber1Dec sans rien y ajouter.

Les dates : getLocalDateStr(date) écrit AAAA-MM-JJ en heure locale (jamais UTC) et c'est la forme stockée ; une ligne de journal ou le bandeau du cumul retournent les trois segments en JJ/MM/AAAA ; les axes de graphe emploient formatDayMonth(date), soit JJ/MM avec zéros de tête. Les durées s'écrivent par formatCalendarDuration(minutes).

formatCalendarDuration(m) :
  total = Math.max(0, Math.round(m))
  total < 60 → `${total}min`
  sinon      → `${Math.floor(total/60)}h${String(total%60).padStart(2,'0')}`

Calories des pas

MET fixe de 3,5, foulée déduite de la taille, marche à 4,2 km/h. Le poids est celui de la date du relevé, la taille celle du profil.

calculateStepCalories(pas, poids, taille) :
    strideKm      = (taille × 0.414) / 100000        // taille en cm → km
    distanceKm    = pas × strideKm
    durationHours = distanceKm / 4.2
    return Math.round(3.5 × poids × durationHours)

getStepsCaloriesForLog(pas, date, weightHistory, profile) :
    poids  = getWeightAtDate(date, weightHistory, profile)
    taille = profile?.height || 170
    return Math.max(0, calculateStepCalories(pas, poids, taille))

Poids à une date

Le poids qui sert aux calories d'un relevé est celui en vigueur à la date de ce relevé, avec quatre replis en cascade.

getWeightAtDate(dateStr, weightHistory, profile) :
    depart = getStartingWeight(weightHistory)          // pesée portant isStartingWeight, 0 sinon
    si weightHistory vide :
        return depart || profile?.targetWeight || 80
    trié = weightHistory trié par date croissante
    actif = depart || profile?.targetWeight || trié[0].weight || 80
    pour w dans trié :
        si w.date <= dateStr  → actif = w.weight
        sinon                 → arrêt (la liste est triée)
    return actif

La pesée de départ se reconnaît à son drapeau isStartingWeight, pas à sa valeur ni à sa place dans la liste. Le tri est fait sur new Date(a.date), mais la comparaison à la date du relevé se fait entre chaînes AAAA-MM-JJ, donc sans fuseau.

Moyennes « Statistiques/j » depuis une date

Un seul calcul sert les deux surfaces qui affichent la carte des moyennes ; seule la borne change. Le dénominateur est le nombre de lignes de la fenêtre, jamais le nombre de journées.

computeStepsStatsSince(stepHistory, startDate, objectif, weightHistory, profile) :
    lignes = stepHistory.filter(log => !startDate || log.date >= startDate)
    si lignes vide :
        return { avgSteps:0, avgProgress:0, avgDistance:0, avgDuration:0,
                 avgSpeed: 4.2, avgCalories:0 }

    avgSteps    = Math.round(Σ log.steps / lignes.length)
    avgProgress = Math.round(Σ Math.min(100, Math.round(log.steps/objectif×100)) / lignes.length)
    avgDistance = parseFloat((avgSteps × 0.00076).toFixed(1))
    avgDuration = stepsWalkingMinutes(avgSteps)
    avgCalories = Math.round(Σ getStepsCaloriesForLog(log.steps, log.date, …) / lignes.length)
    avgSpeed    = 4.2

Trois ordres d'opérations à respecter. La distance et la durée moyennes dérivent de avgSteps, elles ne sont pas la moyenne des distances ni des durées journalières — l'écart tient à l'arrondi. Le pourcentage moyen est la moyenne des progressions plafonnées à 100, journée par journée : une journée à 200 % ne compense pas une journée à 0 %. Les calories sont moyennées après avoir été calculées par ligne, donc avec le poids de chaque date. → fonctionnelle

Sens : hausse, baisse, stable

Le sens compare les deux moitiés de la série de tendance : les sept jours anciens (J−13 à J−7) contre les sept récents (J−6 à aujourd'hui).

periodShift(series, seuil = 0.05) :
    si series.length < 2 → null
    moitie = Math.floor(series.length / 2)
    somme(bloc) = Σ (v ?? 0)
    avant = somme(series.slice(0, moitie))
    apres = somme(series.slice(moitie))

    si avant <= 0 || apres <= 0 :
        si avant <= 0 && apres <= 0 → 'stable'
        return apres > avant ? 'hausse' : 'baisse'

    ecart = (apres − avant) / avant
    |ecart| < seuil → 'stable' ; ecart > 0 → 'hausse' ; sinon 'baisse'

La somme, et non la moyenne : les deux moitiés ayant exactement sept jours, le rapport est le même et se lit sans diviseur. Les trois cas où une moitié est à zéro sont tranchés avant le rapport, qui n'aurait pas de dénominateur. L'accueil appelle periodShift(stepsTrend(appData.stepLogs)) ?? 'stable' : le null d'une série vide — journal sans aucun relevé, stepsTrend rendant alors [] — devient « stable », et la flèche s'affiche quand même. Le seuil de 5 % est un choix de Claude arbitrage non validé.
